### 1.1 一档：在场 3 名不同【巴别塔】干员

> **【巴别塔】干员攻击力、生命值提升（受层数影响）；每有一名【巴别塔】干员所属的其它盟约种类与已计入的不同，
> 全体【巴别塔】干员额外获得攻击力提升（最高+10%）**

| 项 | 数值 |
|---|---|
| 主效果 | 全体【巴别塔】干员 ATK、maxHP ×`(1 + 0.12 + 0.008·L)`（**双属性**） |
| 副效果 | 成员携带的**其它盟约种类**每有 1 种不同，全体成员 ATK **+2%**，**上限 +10%**（5 种封顶） |

- 主效果的斜率与现有汇率一致（≈1%/层）；基础值低于炎（0.23／纯 ATK）与阿戈尔（0.35／纯 HP），因为这是双属性。
- 副效果只数**去重后的盟约种类**、只作用于【巴别塔】成员本身；与机变卡「阿米娅·众志合一」（按场上激活盟约数给全队
  +20/30/40%）的计数对象与受益人都不同。
- **已决议（2026-10-12，OPEN-1）**：副效果**只计本局可用**的盟约——`modeInactiveBonds` 里的盟约不计入种类数
  （与游戏里「本局禁用不显示当前效果」一致）。标准模拟禁用奥术/突袭/投资人等，通常只剩 助力/远见/不屈 3 种 → **+6%**；
  险境及以上可满 5 种 → **+10%**。

### 1.2 二档：在场 6 名不同【巴别塔】干员 —— 「指挥」

> **战斗开始时，攻击力最高的【巴别塔】干员成为【指挥】。【指挥】周围八格内的友方干员造成的伤害提升至 110%，
> 攻击时无视 20% 的防御力和法术抗性。【指挥】被击倒时，指挥权移交给场上攻击力最高的下一名【巴别塔】干员。**

| 项 | 数值 |
|---|---|
| 主效果 | 【指挥】周围八格内的友方干员造成的伤害提升至 110%（每 1 层额外 +0.07%，**最高 180%**） |
| 副效果 | 攻击时无视 20% 的防御力和法术抗性（每 1 层额外 +0.04%，**最高 60%**） |

| 层数 L | 造成伤害 | 无视防御/法抗 |
|---|---|---|
| 0 | 110% | 20% |
| 120 | 118.4% | 24.8% |
| 250 | 127.5% | 30.0% |
| 500 | 145.0% | 40.0% |
| 999 | 179.93%（贴顶 180%） | 59.96%（贴顶 60%） |

  base_def_penetrate:     0.20,  def_penetrate_per_stack: 0.0004,  // 999 层 →  59.96%
  base_res_penetrate:     0.20,  res_penetrate_per_stack: 0.0004,

**判定与移交规则（写死，避免实现分叉）**

| 项 | 规则 |
|---|---|
| 候选范围 | 只从【巴别塔】成员中选 |
| 选取依据 | 战斗开始时的**攻击力快照**（不含战斗中临时 buff），避免战斗中反复换人 |
| 同值平手 | 按部署顺序（`aggroSeq` 靠前者） |
| 移交时机 | 仅在【指挥】**被击倒**（HP 归零）时重选；撤退 / 漏怪 / 替身切换不触发 |
| 移交顺序 | `death` 钩子排在**不屈(10) / 阿戈尔(11) 之后**（低优先级，如 −5），并检查 `unit.alive`，避免「复活了但指挥权已交出去」 |
| 无人可接 | 场上再无【巴别塔】成员 → 光环消失 |
| 光环归属 | 跟随指挥的当前位置（被位移/再部署时光环跟着走） |
| 作用对象 | 只作用于**本玩家**的单位（`ownerId` 过滤；共享战场不越界） |
| 八格朝向 | 不随朝向（八格是完整一圈，旋转不变） |
| 召唤物 | 建议包含（炎佑、医疗探机等也算友方单位）——可改 |
| 实现 | `battleStart` 选指挥 → `passiveBuff` 施光环，每 0.25 s 轮询 + `deploy`/`death` 即时刷新（照灵巧的写法）；层数变化走 `layerGain` → `battle.after(0, refresh)` |

**引擎约定**

- 穿透与**精准**二档的「无视 30% 防/抗」是同一个 mod（`defIgnorePct`/`resIgnorePct`）：**取最高、不相加**
  （沿用引擎既有的 `applyStrongest` 同名取最高惯例，奥术即如此）。否则 60% + 30% = 90% 会把 DEF/RES 抹平。
- 伤害乘区（`dmgDealtMul`）与维多利亚一档相乘——不同盟约本就叠加，可接受；注意两者同时满层时领袖战的
  **限伤**（单次 ≥300000 整次作废）。

- **维什戴尔的 作战能力 写在同一行**（2026-10-12，同一次裁决）：她的固定 +20 / +40 % 与【巴别塔】每 3 层的

  `garrison_168_a/_b`（赫德雷那一对）两条 id，详情卡因此画出两个「作战能力」块（`loadout.js` 渲染每个 id）。

  atk / max_hp 0.01（精锐 0.02） }`，`base_*` 是**固定**半边、无前缀键是**每步**半边，读取器 `attrMods()`
  把两者相加进同一个直接乘算百分比桶。
- **等价性实测**（一次性脚本，同 seed、基础 **500 ATK / 2000 最大生命**、走生产内容路径）：合并成一行后，`巴别塔`
  关闭时三条取样点 = **0 层 600 / 2400、3 层（1 步）605 / 2420、30 层（10 步）650 / 2600**，与「基础 ×(1 + 固定 +
  每步×k)」逐位相符；若固定半边被算两次会读到 700 / 2800，若与按层半边相乘会读到 605 以外的值 —— 都不是实测值。
  `巴别塔` 开启（一档 +12 %）时，同一行的数值整体落在同一个相加百分比桶里，实测 0 层 660 / 2640、3 层 677 / 2708、
  30 层 830 / 3320；旧的「乘数行 + 168」两行写法只在 0 层与它完全相同（660 / 2640），3 层起因乘算而偏高
  （682 / 2728、880 / 3520），这正是把固定半边从 `atkMul` 改成 `atkPct` 后的预期差异。
- **赫德雷的 168 保持原样**（只按层数、无固定半边）；`garrison_03` 族（`bb { atk: 1.2 }`，`battleRuneKey
  char_attribute_mul`，取值是**乘数**）与 `attrByBond`（分数、直接乘算）语义不同，两者不混用。
- **「作战能力 · 按层数」的判定时机按官方收紧（维护者裁决，2026-10-12；DESIGN §29.20）**：`attrByBond` 的按层半边原先
  在引擎里**层数一变就重算**（`layerGain` → `applyReader`），比官方强；官方详情卡那行小字「（※仅在每次部署时判定盟约
  层数）」才是口径，现改为**部署时快照**：同一单位在场时层数上涨**不刷新**，**每次（再）部署**（含精锐 `_b`、突袭落地与
  【移动】）按当刻层数重新判定，**未部署的单位不挂**这个被动 buff。影响面是**全部** `attrByBond` 行（赫德雷 168、维什戴尔
  170 与官方 `garrison_07` / `09` / `11` / `151`… 族），不只是自研那两条。`base_*` 固定半边挂在**同一个**被动 buff 上，
  因此同样从「首次部署」起生效（0 层时点仍给 +20 % / +40 %）；官方把固定半边写在另一条 `garrison_03` / `garrison_137` 行
  时，那条行是 installer（`GAIN_BUFF` / `attr_common_global_buff`），不受本次时机影响。同模块另外三个层数读取器
  （`respawnTimeByBond` 144、`attrByBond_add_onstart` 115 的「部署后100秒内」、`ab_damageScaleByBond` 101）官方文案没有这行
  注解，**保持**随层数更新（144 在击倒时读、115 在窗口内刷新、101 在每次命中读）。
- **`_dealdamage` 读 `damaged` 而不是 `hit`**：设计要求的是**实际造成**的伤害，而 `damaged` 是引擎唯一携带它的
  事件（`damage.js applyHpLoss` 写进攻击者 `stats.dmg` 的同一个数；`hit` 在减伤 / 闪避 / 伤判之前触发）。三条
  `[ASSUMED]` 口径都对齐 `stats.dmg`，不另立定义：① 只算持有者打**敌方**的伤害（自伤与友伤都不计，与
  `source.side !== target.side` 一致；`type === 'element'` 的元素条 chip 不是 HP 伤害）；② **过量伤害不计** ——
  实例被夹到 `max(0, min(amount, target.hp))`，即血条真实掉了多少（`_takedamage` 做不到这点：致命一击后持有者已是
  0 HP，钩子拿不到夹取后的值）；③ **流失**（`battle.loseHp`）不计，与承伤轴对称（它扣 HP 但不是「造成伤害」，也
  从不进入 `stats.dmg`）。跨阈值与 `_takedamage` 一样「无论是否落地都消耗」，并同样用 `busy` 防重入。

**场地依赖（已接受的取舍，维护者 2026-10-12）**：`battle.flags.layerGainsEnabled` 在**联防 / 首领 / 隐秘核心**
战场为 false（`Battle.js`：仅 `kind === 'normal'` 为真；`match/unitePhase.js`、`match/bossRounds.js`、
`match/finalAssault.js` 显式置 false），因此三个 `<战斗中>` 计数器在这些模式里**完全不触发**。此时巴别塔的每回合

  斜率、基础值、或三个计数器的阈值 / 上限。

一件装备 = 四张官方表（`trapChessDataDict` + `trapShopChessDatas` + `effectInfoDataDict`/`effectBuffInfoDataDict` +

| 装备 | ids | 阶 | 基础 | 条件效果 | 进阶 |
|---|---|---|---|---|---|
| 巴别塔誓言 | `chess_item_2_08_e_a/_b` | 2 | 攻防 +5% | `giveBondId: 'babelShip'`：与**变形同构体**（官方的 `canGiveBond` 装备）同装时，装备者视为【巴别塔】成员 | 攻防 +10% |

- **套装条件沿用官方机制**，不新造：伙伴的「无 `_a`/`_b` 后缀」键写在本装备自己的 buff 黑板里
  （`bbStr.equip_chess_id`），与**天马之盔 / 天马之枪**完全一致；引擎的 `carries()` 按**单位**判定，所以
  ① 伙伴的任一品质都满足条件，② 队友身上的伙伴**不**满足条件。`requiresBondId`（必须是某盟约成员）是另一个
  官方字段，这三件都没用它。
- **转职不需要新代码**：巴别塔誓言带 `giveBondId`，官方变形同构体带 `canGiveBond`，引擎既有的配对规则
  （`support/index.js unitBonds`、`match/bondsMeta.js pieceBonds`、research 02 §2.1）只在两者同装于同一干员时授予。
- **护盾走引擎的通用护盾池**（`buffs.js` 的 `shield` / `damage.js` 的 `absorbShields`），不是护盾无人机那种
  「抵消一次伤害」的 `shieldHits`：装备文本说的是生命值口径的「护盾上限」。`[ASSUMED]` 上限属于**护盾池**而非
  单次给予——护盾被消耗后，后续的友方治疗可以把它补回上限（文本写的是「护盾上限」，不是「每次给予的上限」）。
  只计装备者**受到**的友方治疗：`opts.regen`（生命回复速度 tick 不是治疗）与自身治疗都不计，过量治疗不计。
- **进阶的全局放大器**是这一层唯一的全局效果：单一玩家视角的 `hit` 钩子
  （`dmg.type === 'true'` ∧ `c.source.ownerId === 装备者玩家` ∧ `c.target.side === 'enemy'` → `dmg.mul *= 2.5`），
  只由**进阶**记录的 buff 挂载、只挂在装备者身上，且**不会重复乘算**（`dealDamage` 对每个伤害实例只发一次 `hit`；
  处理函数内部再造成伤害会新建 `DamageInfo`，不会回到同一个实例）。引擎里没有可复用的「所有敌人受到的真实伤害」
  放大器——现有的全局倍率是每单位的 `dmgDealtMul`（维多利亚 / 谢拉格 / 协防），它对**所有**伤害类型生效；
  也没有走目标侧 `dmgTakenMul`（真实伤害按 damage.js 头部说明**不吃**脆弱，那样写会静默失效）。

### 6.6 机变「盟誓」卡 —— 凯尔希的盟誓（维护者，2026-10-12；实现见 `tools/content/custom.mjs` 的 `effects` / `effectBuffsPledge`）

官方的「盟誓」族是 8 张 `allybuff_select_2_1`…`_2_8`（`BUFF_GAIN`）：每张只有一条 buff
`global_special_choice_bond_addlayer { count, bond_list }`，文案是「你的<盟约>盟约层数+N，若存在其他队友则他们也获得」，
`decoIconId` 为 `icon_team_buff`（队 buff 图标）。**自研核心盟约巴别塔的盟誓卡 = 第 9 张**：

| 字段 | 取值 | 依据 |
|---|---|---|
| id | `allybuff_select_2_9` | 同族序号接着官方 8 张续 |
| 名称 / 文案 | **凯尔希的盟誓** / 你的巴别塔盟约层数+10，若存在其他队友则他们也获得 | 照抄同族句式；巴别塔没有 2 字简称，所以写全名 |

| buff | `global_special_choice_bond_addlayer`，`bb { count: 10 }`，`bbStr { bond_list: 'babelShip' }` | 同族 key；**层数 +10**（见下） |
| 卡池 | `data/choices.json` 的 `cards.tactic`（`kind: 'ally'`、`team: true`、`stageId: null`） | **派生**：`buildChoices` 把每条 `BUFF_GAIN` effect 收成一张战术决策卡，没有也不需要有 choice event 行 |
| 抽取权重 | 1 | **派生**：`tacticDraft.weights` = 1 + 官方截图里出现过的次数；本卡未被任何官方战术决策截到 → 不在表内 → 1 |
| 可用性 | 只要巴别塔在本局「活着」（`Match.bondLive`：不在模式静态禁用表、卡池里还有棋子）就可能出现 | 与官方盟誓卡同一条通用规则（`cardTargetBonds`）；无额外限制 |

**层数取 +10 的依据。** 同族 8 张的档位是：单盟约的玛恩纳的盟誓（卡西米尔）+12，双盟约的 +10，三盟约的 +8
（斯卡蒂 / 风笛 / 银灰）——即「+10，每多一个盟约 −2，单盟约一档向上取到 +12」。巴别塔是**单盟约**，按这条规律的对位是
玛恩纳的 +12；本卡按维护者给定的 **+10** 落地，比单盟约那一档低一级，也与官方截图里出现最多的盟誓档位一致。
（维护者决定，仓库内无来源，标 `[ASSUMED]`。）

**不需要任何新代码、也不碰别的表。** 生效路径全部是同族的通用路径：`server/match/choices.js` 的
`tacticDraftCards`（出卡过滤）/ `applyDefault` 的 `global_special_choice_bond_addlayer` 分支 →
`PlayerState.addLayers('babelShip', 10, { requireActive: false })`——**无需激活**，与官方盟誓卡一样对未激活盟约照样加层——
对选择者本人与每位存活队友各一次（`team: true`）。`server/sim/content/choices.js` 未改一行：`choiceCardIds` 收全部
`BUFF_GAIN` effect，`registerMeta` 给它们同一个 `TACTIC` handler。**卡面也不需要新资源**：它是普通文本卡，
图标走共用的 `decoIconId`（`icon_team_buff`）。字段总表见 `docs/DATA.md` §19.3。
